# 型システム

SC0 は**普通の依存型**を持ちます。型は第一級の値で、型の中に値（次元・長さなど）が現れます。
型検査は双方向（check / infer）で、定義的等価は NbE（正規化）で判定されます：
`Vec (1 + 2) N` と `Vec 3 N` は同じ型です。

- 宇宙は暫定的に `Type : Type`（type-in-type）。短名 `U` は別名。
- 暗黙の型変換は**ありません**（`N → R` ですら明示。整数添字と実数座標の混同を防ぐ）。
- 変換はすべて `From` クラス一本に載っています（[クラス](user/classes.md#from-と変換)）。

## 基底型

| 正準名 | 別名 | 内容 |
|---|---|---|
| `B` | `Bool` | 真偽値 |
| `N` | `Nat` | 自然数 |
| `Z` | `Int` | 整数 |
| `R` | `Real` | 実数 |
| `Type` | `U` | 宇宙 |

いずれもキーワードではなく `base` モジュールの定義（束縛で隠せる）。

## Π 型と implicit 引数

```
(x : A) -> B          -- 依存関数型
(?n : N) -> Vec n R -> Vec n R -> R     -- ?n は implicit：呼び出し時に推論で補われる
λ?a ?d x y. …         -- implicit を受ける λ（束縛して本体で使える）
```

### 挿入のされ方

- 適用 `f a b …` の elaboration で、各 explicit 引数を当てる前に**先頭に並ぶ implicit が
  自動で埋められます**。関数を引数に渡すだけの位置など、適用がなくても型が要求すれば
  同様に挿入されます。
- check 位置で implicit Pi に普通の式を当てると、**implicit λ が自動で挿入されます**。
  `let f : (?a : U) -> a -> a = λx. x;` のように、定義側で `λ?a.` を書かなくても構いません
  （自分で `λ?a x. …` と書いて束縛を使うこともできます）。

### 埋まり方は 2 種類

implicit の型（ドメイン）によって解き方が分かれます。

1. **nominal 型（クラス）なら instance 探索**：`?d : AddOp a b` のような implicit は
   `instance` 宣言から解決されます（[クラス](user/classes.md)）。
2. **それ以外はメタ変数**：`?n : N` や `?A : U` は単一化（pattern unification）で解かれます。
   メタは局所の束縛変数に依存できます（λ の下でも決まる）。

**⚙ 実装メモ（何から決まるか）**：implicit は、explicit 引数の型か結果型（check の期待型）の
**rigid な位置**に現れるときに「読めます」。rigid ＝ injective な型構成子（`->`・`Vec`・`Buffer`・
nominal 型の頭）を辿って到達できる位置です。逆に、**非単射な関数適用の下**
（`Vec (addN n m) R` の `n` など）や**レコード型のフィールド越し**には一意に逆算できないため
決まらず、注釈が必要になります。

### 明示渡しはできない

**呼び出し側で implicit を明示的に渡す構文はありません**。implicit を特定の値にしたいときは、
引数や全体に `as` で型注釈を付けて推論に決めさせます（`(… as Vec 3 R)` など）。

### 順序に依存しない解決（postpone）

**⚙ 実装メモ**：ある引数の検査が「まだ決まっていないメタ」で詰まっても、そこで止まらず
プレースホルダを置いて先へ進み、他の引数・instance 探索・リテラル解決が進展させたメタで
後から再挑戦します（fixpoint）。「左から右に読んだ順で決まらないと失敗する」ことはなく、
結果型からオペランドが決まるような逆向きの流れも扱われます。それでも最終結果に未解決の
メタが残れば「推論不能」エラーです（黙って埋めない）。

## レコード型

```
{x : R, y : R}
{ j : Topo, coord : Point j -> Vec 2 N }    -- 後のフィールドが前のフィールドに依存できる（telescope）
```

- リテラル `{x = a, y = b}` は期待型と**フィールド名で対応**します（順序非依存）。
- **依存レコード**が書けます：`algebra` の `Monoid m op` は
  フィールド `e : m` を後続の法則フィールドの型（`op e x ≡ x`）が参照します。
  実行時に決まる量を型に持つ値のパッキング（Σ 相当）もこれで表します
  （例：メッシュ演算が `{ j1 : Topo, pos : Point j1 -> Vec 3 R }` を返す）。

## Vec と Buffer

```
Vec n T               -- 長さ n : N が型に現れるベクトル。R³ = Vec 3 R
Buffer d shape T      -- 実体化されたバッファ。shape : Vec d N（例 Buffer 2 [64, 64] (Vec 3 R)）
```

- 次元・長さの不一致は型エラー（`dot : (?n : N) -> Vec n R -> Vec n R -> R` が n の一致を強制）。
- 軸数 `d` は**常に静的**です（動的次元はない）。サイズは型レベルで追い、
  実行時にしか決まないものは依存レコードで存在パックします。
- `append : Vec n T -> Vec m T -> Vec (n + m) T` のように**型の中に演算子**が現れます
  （型レベルの `+` も値と同じ overload 解決）。

## enum

```
enum Maybe a { some a, none };        -- 宣言（payload 付き・型パラメータ可）
let Interp = enum { nearest, linear, cubic };   -- 匿名 enum 型を let 束縛
```

- タグは型への射影で取り出します：`Interp.nearest`。
- payload 付きコンストラクタ（`some`）は宣言時に束縛される**ただの関数**で、
  principal type を持ち infer 位置でも使えます（`some true : Maybe B`）。
- 分岐は `case e of { some x => …, none => … }`。**網羅必須**。
- 制限：**再帰的な enum は書けません**。また `case` の結果型が分岐対象に依存する
  依存 case はサポートされず、honest に拒否されます。

**⚙ 実装メモ**：「関数としての `some`」と「内部タグとしての some」は別物です。
enum 型そのものは nominal（剛体）で、コンストラクタ関数を経由してのみ構築されます。

## nominal 型

```
nominal Complex = Vec 2 R;
nominal Fin (k : N) = { i : N, lt : Lt i k };
nominal Semigroup m (op : m -> m -> m) = { assoc : … };   -- 値パラメータは型注釈の形で書く
```

`nominal X = RHS` は **RHS と定義的に等しくない、剛体な名前つき型**を作ります。
`Complex` と `Vec 2 R` は別の型で、`Complex` を期待する場所に `Vec 2 R` の値は入りません。

- **RHS はレコード型か Vec に限られます**（それ以外は宣言時に拒否）。
- パラメータは explicit のみ。値パラメータ（`op : m -> m -> m` のような）も取れます。
- パラメータについて **injective** に扱われるため、`Point j` から `j` が推論できます
  （メッシュの `?j` 推論はこれに乗っています）。
- 射影は透過です：`c.0`（`Complex = Vec 2 R` の成分）や `f.i`（`Fin` のフィールド）は
  そのまま使えます。**剛体なのは型の同一性だけ**です。

### 構築＝リテラルの born-as

nominal 型の値は「リテラルがその型として生まれる」ことで作られます。

```
let z : Complex = [1.0, 2.0];        -- Vec リテラルが期待型 Complex として生まれる
iterate 24 [0.0, 0.0] step           -- 結果型が Complex なら注釈不要（文脈から born）
[1.0, 2.0] as Complex                -- 明示するなら as（これも注釈であって変換ではない）
```

**⚙ 実装メモ**：check がリテラル（Vec / レコード）を見たときだけ nominal を unfold して
中身を検査します。既存の `Vec 2 R` の**値**を `Complex` に変換する組み込み手段はありません
（`as` は coercion ではない）。文脈から期待型が決まらないリテラルは、構造的な Vec 型に
フォールバックします。この born の解決は数値リテラルの `From` と同じ遅延機構に乗っており、
「nominal は本質的に恒等の辞書 `From RHS X`」として扱われます。

## 命題的等価（Id / ≡）と J

```
Id A a b       -- 原始（base）。中置糖衣 a ≡ b（std・型 A は推論）
refl           -- 反射律
trustMe        -- 公理：任意の a ≡ b（ユーザー責任・痕跡は項に残る）
J              -- 除去子（唯一の原始）。transport / sym / trans / ap / castVec は std が J から導出
```

- **証明は普通に書けます。書けるなら書くべきです**。`std` 自身も `sym` / `trans` / `ap` を
  `J` から本物の証明として導出しています（trustMe 不使用）。
- `trustMe` は「**主張は正しく立てるが、その正しさは trust me（引き受ける）**」という回避手段です。
  基底型の性質（`N` の算術法則など）は言語内に induction が無く証明できないため
  **postulate として** trustMe で立てられています（`std` の
  `plusComm` / `plusAssoc` / `plusZeroR` / `mulComm` / `mulAssoc`）。
  証明が面倒なときの逃げ道としても使えますが、痕跡は項に残ります。
- `Vec` 長の付け替えなどは `castVec (plusComm n m) v` のように法則と組み合わせて使います。
- **型と証明は実行時に消去されます**。`Vec n T` と `Vec m T` は同じ表現で、
  `J` / `transport` は実行時には恒等です。

**⚙ 実装メモ（trustMe の実行時検査）**：`J` の簡約時、等式の両端 `a` / `b` が具体値なら
**実行時に a ≡ b を検査**します。`trustMe` で嘘の等式（例 `2 ≡ 3`）を作って `transport` しても、
評価がその場で honest なエラーになります（型健全性は破れても panic や黙った誤動作にはならない）。
両端が未確定（neutral）の間は `J` は簡約されず stuck に残ります。関数どうしの等式は
判定不能なので検査されません。

## Lt と Fin（有界添字）

```
Lt : N -> N -> U                          -- 「より小さい」命題（証拠を持つだけの型・消去子なし）
nominal Fin (k : N) = { i : N, lt : Lt i k };
```

配列 `Array k A` の全域添字に使います。`Fin` の**唯一の作り口は `clampFin`**です：

```
clampFin : (?k : N) -> N -> Fin k    -- 添字を常に [0, k-1] へクランプして Fin を作る
```

名前のとおり**常に範囲内へ丸める**（範囲外を渡すと末尾に寄る・エラーにしない）ので、
作られる `Fin` は必ず範囲内＝範囲証拠 `Lt i k` は postulate ですが**嘘になりません**。
メッシュの接続子などプリミティブ層も同じ口を通ります。決定手続きやソルバはありません。

**⚙ 実装メモ（既知の推論穴）**：`at a (clampFin (floorN …))` のような自前の index 計算では、
`?k` が結果型からしか決まらず推論が届かないことがあります。原理的な壁ではなく
`as Fin k` で pin できます（Fin 推論の改善は今後の課題）。

## ホールと未完成

- `?` は期待型を**報告**するホール。`?` を含むプログラムは「未完成」という正規の状態で、
  エラーではなく各ホールの型が提示されます。
- `_` は推論で決まるなら黙って埋まるワイルドカード。決まらなければ推論不能エラー。

## エラー報告

- 型エラーは**宣言ごとに多重化**されます：ある宣言が失敗しても、その宣言は
  「注釈された本物の型を持つ止まったメンバ」として扱われ、後続の宣言は正しい型で
  検査が続きます（カスケードエラーを抑制。値は捏造しない）。
- エラー位置は宣言内の**正確な項**に紐づきます（LSP / Web で該当箇所が示される）。
  例外：インスタンス解決の失敗（no instance）は横断的なため文書頭に出ます。
