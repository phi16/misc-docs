Oven ── 言語の記録

Oven とは

Oven は 依存型(MLTT)+ 帰納型 + QTT(数量的型)を核に持つ純粋関数型言語で、書いたコードを GPU で並列実行できる ことを目指す実験的言語です。処理系は Rust で実装されています(コアは外部依存ゼロ)。

一言でいえば:

「依存型を持つ純粋関数型言語で、しかも GPU で並列計算が走って、画像・音・アセットが作れる」

という、互いに引っぱり合う性質の欲張りな組み合わせです。この文書群は、その緊張をどうほどいたか(あるいはまだほどけていないか)の 記録 です。チュートリアルではなく、「この言語がどういう原理で出来ていて、なぜそうなったか」を、設計上の特徴から細かい言語機能までまとめてあります。

何をしたい言語か

  • 並列計算:たくさんのデータに同じ計算を一斉にかける。GPU(compute shader)で走らせる。
  • creative coding:Shadertoy 的・Processing 的に、コードから画像や音を生成する。procedural generation。
  • アセット生成:Unity で使えるメッシュ・テクスチャをコードで吐き出す(将来)。
  • これらを 強い静的型付け・純粋関数(副作用なし)・全域(すべての計算が停止する) の上でやる。

なぜこの組み合わせか ── 4 つの世界の統合実験

この言語の動機には、はっきりした個人的背景があります。作者は Rust を書き、Agda を使い、Shadertoy を使い、Houdini を使う ── 普通は交わらない 4 つの世界を日常的に行き来する人間です。そして、これらの世界は離れて見えて 綺麗に統合できる はずだ、という直観があります。Oven はその直観を確かめる実験です。

  • Agda からは依存型と全域性を ── ただし証明のためでなく、コンパイルの道具として。
  • Rust からは資源の規律を ── ただし参照と lifetime は捨てて、線形性だけを。
  • Shadertoy からは「画像 = 座標の純粋関数」というモデルを ── ただし型を付けて。
  • Houdini からは procedural generation(recook = 再評価という参照透過性、per-point 並列、attribute = レコード)を ── ただし言語として。

各章で見るように、これらの要求は妥協で繋がっているのではなく、多くの場所で 同じ一点を指しています(全域性は型理論の衛生であると同時に GPU の物理的制約であり、'0 消去は proof irrelevance であると同時に単相化の根拠です)。その合流の詳細は他言語との比較の結びで扱います。そして Oven は終点ではなく、「もっといろんなものが綺麗に表現された言語がありうる」という信念の、最初の一歩という位置づけです。

雰囲気:マンデルブロ集合を GPU で描く

examples/showcase.ov の抜粋です。純粋なヘルパ関数(レコード・中置演算子・反復・分岐)をトップレベルで定義し、それを GPU カーネルから呼びます。カーネル境界でヘルパはインライン展開され、iterate(16, …) は静的アンロールされます。

// レコード = 名前付き Σ。型エイリアスはただの定義
Complex  : Type = (re : F32, im : F32);
EscState : Type = (z : Complex, cnt : U32);

// z² + c(中置演算子とレコード射影 ── host でも GPU でも使える普通の関数)
stepC : (c : Complex, z : Complex) -> Complex
  = λ(c, z) (z.re * z.re - z.im * z.im + c.re, 2.0 * z.re * z.im + c.im);

// エスケープ反復:|z| ≤ 2 の間だけ z ← z²+c を進めて数える
escape : Complex -> U32
  = λ(c) (iterate(16, λ(s : EscState)
            case(ltF32(norm2(s.z), 4.0)) {
              true  => (stepC(c, s.z), s.cnt + 1[U32]),
              false => (s.z, s.cnt)
            }, ((0.0, 0.0), 0[U32]))).cnt;

// 8×8 グリッドの各スレッドが 1 画素を計算して out に書く
let '1 out : Buffer(64[U32], Color) = newBuffer(64[U32]);
dispatch(i in (8[U32], 8[U32], 1[U32])) {
  store(out, i.1 * 8[U32] + i.0, toColor(escape(toC(i.0, i.1))))
};
readback(64[U32], out)

out は線形('1)資源で、dispatch が borrow-lift(消費して返す)します。store の効果順序は零幅の GPU token を暗黙に threading することで型に強制されますが、ユーザは token を一切書きません。

動かし方

cargo run -- examples/showcase.ov        # 型検査 + CPU emulation(正規化結果を表示)
cargo run --features gpu -- --gpu examples/gpu.ov   # 実 GPU(wgpu)でも実行
cargo run --example mandel --features gpu           # 512×512 のマンデルブロを PNG に
cargo test                               # テストスイート(190 本超)

この文書の性格と読み方

  • これは 記録 です。人へ教えるためのチュートリアルではなく、「Oven という言語がどういうものか」を将来参照できる形で網羅することを目的とします。
  • 実装済み・設計のみ・撤回済みを区別して書きます。設計途中の言語であり、確定していないものには印を付けます。
  • 設計の一次資料はリポジトリの DESIGN.md(journal 形式の設計ノート)と docs/(type-system / syntax / effects / library の 4 分冊)です。この文書群はそれらを別の体系に編み直したものです。
