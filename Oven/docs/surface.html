Oven ── 言語の記録

表面言語 ── 構文と糖衣

この章は Oven の書き方(文法)と、それが何に展開されるか(desugar)をまとめます。方針は一貫しています:

すべての糖衣は、剥がすと必ず素の Π・Σ・multiplicity になる。糖衣のために新しい意味論を足さない。

字句

// 行コメント
/* ブロックコメント */

-- はコメントに使いません(+--+ のような演算子の並びと衝突するため)。Unicode 記法を歓迎します(λ・→・'ω・⟦⟧・Σ など)。ASCII 代替も常にあります(\・->・[[w]])。VSCode 拡張は \name + Space での Unicode 入力を提供します(\lam→λ、\to→→、\ih→⟦⟧ など)。

既知の字句の罠:]] は ⟦⟧ の ASCII 代替 [[w]] の閉じと、入れ子の [ の閉じが衝突します。当面はスペースで回避します。

テレスコープ:implicit [...] と explicit (...)

関数の型は「先頭に implicit テレスコープ [...] を 1 つ(省略可)、続いて explicit テレスコープ (...)、`→ 結果」:

map : [A : '0 Type, B : '0 Type] (n : Nat, f : A → B, xs : Array(n, A)) → Array(n, B)

テレスコープ項目の文法:

'p A          // 無名・multiplicity p
x : 'p A      // 名前付き
x y : '1 A    // 複数の名前を同時宣言
A → B         // 単一の無名 explicit 引数は括弧を省ける
  • ' の有無が曖昧性を解消します:(p x : A) は「p と x の 2 宣言」、('p x : A) は「x を量 p で」。
  • implicit 節は先頭に 1 つだけ。implicit は implicit にしか依存できません。だから証明義務は implicit に隠さず explicit に書きます:safeIndex : [A : '0 Type] (n : Nat, xs : …, i : Nat, p : '0 Lt(i, n)) → A。
  • implicit 群もカリー化されています([A, B] ≡ [A][B])。各 implicit は独立したメタ変数として 1 つずつ解決されます。

適用

f(x, y)          // tight。全面 curried なので = 並置 f x y = (f x) y
f x y            // 並置でも同じ
f((x, y))        // タプル (x, y) を 1 個渡す(f が Σ を取るとき)── f(x, y) とは別物
f (x, y)         // 注意:( の前の空白で loose = タプル適用。tight が curried
map[A, _](n, …)  // _ で一部の implicit だけ推論
map[A, ..](…)    // .. で後ろの implicit を一括推論

tight(空白なし)と loose(空白あり)で意味が変わる点は、この言語の構文で最も注意が要る箇所です。

型位置では:矢印の前の (x:A, y:B) はテレスコープ(= curried 引数列)、単独なら Σ 型。値の (a, b) はタプル。「型構築」と「値構築」が文法上分離しているので Σ キーワードは不要です。

ラムダ

λ(i) body               // 括弧必須。\ でも λ でもよい
λ(x, y) body            // テレスコープを束縛するので複数引数可(curried)
λ[A : '0 Type](x) body  // implicit テレスコープも書ける
λ[&World](s) body       // [&X] = threaded capability の宣言(効果系の章)

リテラル ── 型の指標を持つ

リテラルは期待型から解決されます:

0            // 期待型が Nat なら zero、F32 なら 0.0、Mult なら multiplicity 0
0[Nat]  1.5[F32]  5[U32]   // 型を明示(この [T] は implicit 適用と同じ記法)
2 : Fin(5)   // Fin リテラル(2 番目の Fin 値に解決)

期待型が無い文脈(注釈なしの let x = 5)では注釈必須です ──「その場で勝手に既定の型を決める ad-hoc な動作は認めない」という方針によります。elaboration は Tm::Lit を期待型から具体形(Mult の 0/1、Nat の succ^n zero、機械スカラ)へ解決し、以降の評価は解決済みの core 項を使います。

ブロック・定義構文・module

{
  x = f(a);                    // 値束縛(let は省略可)
  g(y : Nat) : Nat = y * y;    // 局所関数定義(= g = λ(y) y*y)
  let '1 out = newBuffer(n);   // graded let(mult は名前の前)
  release(buf);                // 出力のない文。; は「結果を drop して継続」
  g(x)                         // 末尾の ; 無し式 = ブロックの値
}
  • 定義構文:name [params] [: T] = body ; を入れ子 let へ脱糖します。パラメータは LHS に 1 回だけ書き、f[A](x : A) : R = body は f : [A](x : A) → R = λ[A](x) body 相当。: T 省略時は body から推論。explicit パラメータ群は tight ( のみ(λ 本体が括弧で始まる場合と区別するため)。
  • ; の drop 規則:() は自明に drop 可。線形値を ; なしで放置したり、暗黙に drop するのはエラーです(非 Unit の drop には将来 Consumable 能力が要る設計)。
  • 名前付きレコード構築:(f = e, g = e) は値から型を推論し、書かれた名前を Σ 型に乗せます。r.f(名前射影)と r.0(位置射影)は一致します。

module は「params を取り名前付きレコードを返す関数」への糖衣 です。専用機構はありません:

module Vec3 (n : U32) {
  zero : U32 = 0[U32];
  scale (s : U32, v : U32) : U32 = mulU32(s, v);   // 兄弟 zero も参照できる(内部は nested let)
}
Vec3(3[U32]).scale(2[U32], 5[U32])   // = 10

params は省略可能で、その場合は素のレコード値になり M.field で直接アクセスします。open(無修飾取り込み)は未実装です。

演算子と instance

typeclass は「Σ レコードを implicit 引数で渡す」だけで、専用機構はありません。演算子は mixfix 宣言(Agda 流に _ を引数位置に置く)+ fixity 宣言で、演算子は一切特別扱いされません:a op b → _op_(a, b) へ脱糖され、_op_ は instance(辞書)で解決されます。

infixl 6 _+_                // 中置・左結合・優先順位 6
infixl 7 _*_
prefix 9 ~_                 // 前置。`~ x` → `~_(x)`

// クラスは nominal(名目的型)。中身は二項演算の型そのもので、値は演算関数そのまま(wrapper なし)
nominal Mul (A : Type) = (x : A, y : A) → A
_*_[A : '0 Type, d : Mul(A)](x : A, y : A) : A = d(x, y)

// instance は implicit 宣言したものだけが暗黙解決の対象(グローバル探索ではない)
implicit mulF32d : Mul(F32) = mulF32

// パラメトリック instance(前提辞書 da/db を使う)── Haskell の instance Eq a => Eq [a] 相当
implicit eqPair [A B : Type, da : Eq(A), db : Eq(B)] : Eq((a : A, b : B))
  = λ(p, q) da(p.0, q.0) && db(p.1, q.1);

instance 解決の仕組み

本質は「implicit 引数 = メタ変数。それが曖昧性なく埋まりさえすればよい」です:

  • メタの埋め方は 2 つ:(i) 単一化で構造的に決まる(型パラメータ)、(ii) 文脈の implicit 印つき束縛から 型一致で一意に 拾う(辞書)。複数一致は曖昧エラー(coherence)。
  • on-demand 解決:メタの型が ground になった時点で解決を試みます。連想型の戻り値(d.Out)が辞書 d の解決後に射影簡約で解ける ── 遅延一括では原理的に無理な形です。
  • パラメトリック instance:プール値が Π 型なら fresh メタを当てて結果型を単一化し、前提辞書を再帰的に解決します(自己参照の無限ループは深さガードで防止)。
  • 制約引数は自動 instance:nominal 型を持つ束縛([d : Mul(A)] の仮引数等)は自動的に解決プールに入ります。よって総称関数の中で演算子をそのまま書けます:
square [A : Type, d : Mul(A)] (x : A) : A = x * x;   // d(x, x) の明示適用は不要
  • implicit foo; は既存の(非 implicit)束縛を以後の instance プールへ追加します(再エクスポート)。ブロック局所でも効きます。
  • どう埋めたかは解決トレースで内省できます。

クラスが nominal である理由

構造的な Σ レコードでクラスを表すと、同形のクラス(Add(F32) と Mul(F32) ── 中身はどちらも (F32,F32)→F32)が structural conversion で同一視され、instance 解決が曖昧になります。nominal は conversion でだけ不透明で、構築・適用・射影には透明(値は素の演算関数)── 解決の一意性のためだけの最小の名目性です。

結果型を A(homogeneous)にする理由

_*_ の結果を連想型 d.Out にすると、リテラル被演算子(2.0 * 3.0)で型パラメータ A が ground にならず、instance 解決がデッドロックします(被演算子の型が未確定で、結果型も A を固定しない)。結果を A にすれば期待型が A を直接解き、リテラルも辞書も解けます。heterogeneous な連想型版は被演算子の型が確定している場面でのみ使う、という整理です。

ambient prelude

演算子 _+_/_-_/_*_/_/_/_⊔_・クラス Add/Sub/Mul/Div/Lub・Mult の instance は 全プログラムのスコープに常在 します(処理系がユーザソースの前に prepend)。1 + 1 が ω に評価されるのも、この ambient instance の解決結果です。

データ宣言・分解の書き方

data Name [implicit params] (explicit params) : (indices) → Type {
  ctor : <GADT スタイルの完全な型>,
}

case[P](v) { ctor1(xs…) => body1, ctor2(ys…) => body2 }
  • motive [P] は省略可(非依存なら期待型から)。全 constructor をちょうど 1 つずつ書きます(ワイルドカードは未実装)。
  • 本体では ⟦w⟧(帰納仮説)を再帰パターン変数にだけ適用できます。→ コア型理論

借用の書き方

// 型:& は型の頭(multiplicity と同じ位置)
set : [A : Type] [n : '0 U32] (&Array(n, A), i : U32, x : A) -> Unit

// 呼び出し:値側も & を付ける。以降の a は更新後を指す(同名へ再束縛)
set(&a, 2[U32], 7[U32]);

// ユーザ定義の借用関数(借用群は最後・名前付き・: R 必須)
incAt (a : &Array(n, U32), i : U32) : Unit = {
  let v = get(&a, i);
  set(&a, i, v + 1[U32]);
}

脱糖規則(確定分):

  • 入力は表面の順のまま(&T → '1 T にするだけ)。出力だけ threaded を出現順に先頭へ集め、本来の結果を最後に 1 つ:(A, &B) → (C, D) ⟿ (A, '1 B) → ('1 B, (C, D))。
  • destructure 側は常に threaded 先頭:f(a, &b) ⟿ let (b, c) = f(a, b)。
  • & を書けるのは「任意の Π 型の、入力側の直接のテレスコープ」だけ。データのフィールドや Array(n, &B) のような入れ子には書けません(& は「この関数がこの引数を consume-and-return する」という関数の印なので)。
  • 1 つの文に効果ある部分式は 1 つまで(順序は ;/let だけが作る)。

効果 [&X] の書き方・意味は効果系の章を参照してください。
