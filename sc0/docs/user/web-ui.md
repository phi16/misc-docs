# Web 環境

ブラウザで動く編集環境です。起動は [動かし方](user/getting-started.md#web-環境)。
SC0 の中心的な使い方——テキストとノードの双方向編集・ライブなプレビュー——はすべてここにあります。

## 原則：真実はソースひとつ

プログラム（宣言の列）が唯一の真実で、テキスト（Source）もノードグラフ（Graph / Workspace）も
その**ビュー**です。どちらで編集しても同じ実体が変わり、往復で意味は変わりません。
ノードの位置や view 指定のような「意味に効かないが意図に効く」情報は、
`#[node]` 注釈という透明な層としてソース側に保存されます。

特別な `main` はありません。**各宣言（ノード）がそれぞれ出力になり得ます**。
サンプルの多くが `let output = …;` を終端に置いていますが、これは初回選択の既定に
使われる名前の慣習であって、言語機能ではありません。

## タイル窓の操作

i3 風の 2 階層タイルシステムです：デスクトップに複数の浮遊トップレベル窓があり、
窓の内部は水平分割・垂直分割・タブのコンテナ木になっています。

| 操作 | 効果 |
|---|---|
| タブ／チップをドラッグ → 別パネルの**中央**に落とす | タブとして重ねる |
| 同 → 別パネルの**辺**に落とす | その方向に分割 |
| 同 → 素のデスクトップに落とす | デタッチ（新しい浮遊窓） |
| タブバーの空きをドラッグ | 窓の移動 |
| 窓の縁をドラッグ | リサイズ |
| ⛶ | 全画面（最背面の背景窓になる） |
| タスクバー | パネルの出し入れ（閉じたパネルの再表示） |

レイアウトは localStorage に保存され、次回起動時に復元されます。

## 選択と評価

- Workspace でノードをクリックすると**選択**され、その宣言が Graph / Code / Result の対象に
  なります。空所クリックで選択解除（何も選択しない状態も正規）。
- 評価されるのは「選択ノード ∪ view 付きノード ∪ popup で開いているノード」です。
  **view の評価は可視性に依存しません**——画面外にスクロールしても値は最新に保たれます
  （音が鳴り続けられる土台）。
- 評価は worker 上の incremental エンジン（Cook）で走り、UI はブロックしません。
  編集中に届いた古い評価結果は捨てられます（最新のリクエストだけが反映される）。

## Workspace：宣言の編集

- **自動レイアウト**：依存の深さで縦位置・連結成分ごとに横をパッキング。
- **ドラッグで自由配置**：位置は `#[node]` の `pos` としてソースに永続化され、
  そのノードは自動レイアウトから外れます。
- **追加**：Workspace 上で Space → カーソル位置に名前入力欄 → Enter で
  `let <名前> = ?;` が**その位置に**作られます（名前が空なら自動採番）。
- **削除**：Delete / Backspace は 2 段階（Houdini の bypass → delete 風）。
  body が `?` でなければ 1 度目は **hole 化**（body を `?` に・ノードは残る）、
  既に `?` なら 2 度目で**本当に削除**（このノードへの参照は `?` になる＝黙って壊れない）。
- rename・connect / disconnect（ホール ↔ 兄弟参照）は Info / Graph 側の編集から行えます。
  rename は参照側も連鎖して追従します。
- ホールを含むノードは専用色で描かれ、空きスロットが一目で分かります。
- 左ドラッグ＝選択・ノード移動、右／中ドラッグ＝パン、ホイール＝ズーム。

## Graph：1 宣言の中身の編集

選択宣言の body を**全展開**した式グラフです。λ / let は入れ子の「領域」として描かれ、
変数は束縛への参照ノードになります（同じ束縛の使用は 1 ノードを共有）。

- hover / クリック（pin）でノードを focus すると、**変数はその束縛元を、領域はそれを使う
  変数群を**ハイライトします。focus 中のノードの詳細・編集は Info パネルに出ます。
- Info からは部分式の**テキスト編集**（その部分木だけ差し替え）、**fold / unfold**、
  let のヘッダ（名前・型・値）編集ができます。UI とテキストで能力差はありません。
- 兄弟宣言への参照（`member_ref`）と、宣言そのものを表す**出力 sink** は別の見た目で
  描かれます。

## ノードの粒度と折り畳み `@`

Graph は式を展開してノード化しますが、細かすぎるときは
**`@` マーカーで部分式を 1 ノードに畳めます**（[構文](user/syntax.md#折り畳みマーカー-表示専用)）。

```
let f : N -> N = λx. @((x + 1) * x);      -- (x+1)*x が 1 ノードになる
let output = λy. let @x = (y + 1) * 2 in x + y;   -- 値を let ノードに吸収
```

- 畳んだノードは**自由変数だけが入力ポート**に出て、本体は閉じた式のテキストとして
  ノードの中に収まります。専用の色で表示されます。
- `@"name"(…)` で表示名を付けられます（無名なら `@`）。
- Info パネルの fold / unfold ボタン・名前欄と等価です（`@` はソースに保存される
  表示専用の装飾で、意味には効かない）。

## `#[node]` 注釈と view

宣言の直前に `#[node] {…}` を書くと、そのノードの表示を指定できます。
**意味には一切効かず**、往復で保存されます（core は解釈しない透明メタデータ・JS だけが読む）。

```
#[node] {view:"print"}
let a = 3.0 + 4.0;                    -- 箱に「値 : 型」を表示

#[node] {view:"image", size:[120, 120]}
let pic = rasterize {…} (λp. …);      -- 箱に画像を描く

#[node] {view:{type:"slider", min:0.0, max:1.0, step:0.01}}
extern amp : R = 0.5;                 -- スライダ（入力 view・extern＝実行時入力）

#[node] {pos:[320, 40]}
let b = …;                            -- 自由配置の位置（ドラッグで自動的に書かれる）
```

view の種類：

| view | 対象 |
|---|---|
| `print` | 任意の値（`値 : 型` 表示） |
| `image` | `Buffer 2 [w,h] (Vec 3 R)` などの 2D バッファ |
| `curve2d` | `Buffer 1 [n] (Vec 2 R)`（平面曲線） |
| `curve3d` | `Buffer 1 [n] (Vec 3 R)`（空間曲線） |
| `surface` | `Buffer 2 [m,n] (Vec 3 R)`（曲面・高さ場） |
| `mesh` | `{j : Topo, pos : Point j -> Vec 3 R, …}` レコード（3D） |
| `audio` | `Buffer 1 [n] R`（mono）/ `Buffer 1 [n] (Vec 2 R)`（stereo） |
| `slider` | 数値の**入力**（`R`・多成分なら `Vec n R` も葉ごとのスライダに・次元別の min / max 可）。min / max / step は**著者が明示**（型からは出ない。未指定なら「未指定」と正直に出る） |
| `toggle` | `B` の**入力**（トグル） |
| `color` / `point` | `Vec 3 R` / `Vec 2 R` の**入力**（色・座標のエディタ。数値葉ベースで let / extern 共通） |
| `stream` | `Stream _` の**ライブ再生**（▶ / ⏹。[音とストリーム](user/stream.md)） |
| `button` | `extern hold x : Trigger Unit;` の**発火ボタン**（押下の瞬間に発火） |
| `graph` | その宣言の **AST グラフ**（Graph パネルと同じ描画の埋め込み・縮小版） |

view 無しのノードは小さな○、view 付きは箱＋I/O ポートで描かれます。
`size` は箱の大きさです。

### slider のライブ編集

slider を付ける宣言は 2 種類あり、挙動が違います。

- **`extern`（推奨）**：`extern amp : R = 0.5;`。値はソースに属さない**実行時入力**なので、
  ドラッグしても**ソースは 1 文字も変わりません**。再ビルドもカーネルの再コンパイルも
  起きず、コンパイル済みカーネルに新しい値を流すだけ——もっとも軽いライブ経路です。
  `init`（`= 0.5`）はまだ値が供給されていないときの既定値です。
- **`let`**：値はソースの一部なので、ドラッグするとソースの**その値のリテラル箇所だけ**が
  書き換わります（全文の再生成ではないので、エディタのカーソルや他の行は動きません）。
  変わった宣言とその下流だけが再計算されます。

どちらもドラッグ中は画像などの下流 view がリアルタイムに追従します。迷ったら
「作品のパラメータは extern・定数の調整は let」くらいの使い分けです。

### 音のライブ再生とライブコーディング

- `stream` view の ▶ で鳴り始めます（初回はエンジン起動で数秒「⋯」が出ます）。
  鳴らしながら動かせるのは **`extern hold`** の slider / button です（素の extern は
  再生開始時点の値で焼き込まれます——[音とストリーム](user/stream.md#宣言の-22let--hold--extern--extern-hold)）。
- **`hold` 宣言のコードは、鳴らしたまま編集できます**。Run すると走行中の音が
  crossfade（約 15ms・Trigger は即時差し替え）で新しい定義に繋がります。編集が
  コンパイルできない間は直前の正常な音が鳴り続けます（livecode / livesynth サンプル参照。
  規則と反映の粒度は [音とストリーム](user/stream.md#宣言の-22let--hold--extern--extern-hold)）。
  Workspace では hold ノードは専用色（オレンジ）で描かれます。
- **Live パネル**で走行状態（どの hold が生きているか・crossfade 中か・voice 数など）を
  実際に確認できます。
- 再生が実時間に間に合わないと Log に `audio underrun: …` が負荷内訳つきで出ます。
- `midiIn` を使うストリームは、再生開始時にブラウザの MIDI 許可を求めます。

### Pop out（view を窓に出す）

Workspace Info の「Pop out view」で、選択ノードの view を独立した窓としても開けます
（view 注釈が無いノードは `print` で開く）。

- **箱の view と窓の view は同時にライブ**です（同じノードの評価結果が両方に流れる）。
- 窓のときだけ操作 UI（zoom / fit / 露出調整・3D の回転・音の再生など）が出ます。
- 参照しているノードが削除されると窓は**空表示**になります（勝手に閉じたりエラーを
  出したりしない——不在は正規の状態）。別プログラムをロードすると popup は閉じられます
  （同名ノードへの誤接続を防ぐため）。

## レンズ（Result の見方を選ぶ）

選択ノードの評価結果がバッファなら、**その形に合う解釈だけ**がボタンとして並びます
（自動判定はしません——「何として見るか」はユーザーが選ぶ）。

| レンズ | 対象の形 |
|---|---|
| image (2D) | 2 次元・1〜4 成分 |
| image (1D) / image (wrap) | 1 次元（wrap は長い 1D を正方形に折り返し） |
| curve (2D) / curve (3D) | 1 次元・2 / 3 成分 |
| audio | 1 次元・1（mono）/ 2（stereo）成分。Web Audio で再生 |
| surface | 2 次元・3 成分 |
| mesh (3D) | メッシュレコード（バッファではなく Topo＋属性関数から抽出） |

押すと対応するビューアがタイル窓として開きます。

## Log パネル

評価のたびに時系列で**蓄積**されます（消えない）：

- 型検査・評価の所要時間（宣言ごと）
- `cook <ノード名>: X ms` — incremental 再計算にかかった時間（再計算されなかったノードは出ない）
- render の実行経路（**IR コンパイルか per-sample フォールバックか**・次元・サンプル数）
- 構造編集がソースのどの行範囲を書き換えたか（`edit <名前>: [12, 15)` の形）
- エラー

「思ったより遅い」「IR に乗っていないのでは」と疑ったら、まずここを見ます。

## Cook（incremental 再計算）

**⚙ 実装メモ**：編集のたびに全体を再ビルドはしません。ビルドは宣言単位でキャッシュされ、
編集は該当宣言を dirty にするだけ、評価要求が最小限の再計算を引きます（early cutoff つき：
再計算の結果が前と同じなら下流に伝播しない。たとえば `pos` 注釈の変更は値に効かないので
下流は動かない）。fixity / nominal / instance / enum / import の変更だけは影響範囲が
暗黙的なので全体を再計算します。
