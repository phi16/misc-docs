# 構文

SC0 の表層構文は関数型言語寄りです。関数適用は並置 `f x`、抽象は `λx. e`。
プログラムは**宣言の列**（各宣言は `;` で終わる）です。

## 字句

- コメントは `--` から行末まで。
- **識別子に Unicode が使える**（`λ` は構文、`≡` や ギリシャ文字は名前に使える）。
- `let` / `opaque` / `nominal` / `enum` / `instance` / `import` / `open` / `private` /
  `infix` / `infixl` / `infixr` / `if` / `then` / `else` / `case` / `of` / `as` / `in` がキーワード。
- `N` / `Z` / `R` / `B` / `U` / `Type` などの型名は**キーワードではなく**普通の名前
  （`base` モジュールが定義しており、束縛で隠せる）。

## 宣言

| 形 | 意味 |
|---|---|
| `let x : T = e;` | 値の定義（型注釈は省略可：`let x = e;`） |
| `opaque x : T;` | 本体を持たない定義。実装は処理系がネイティブに供給する（ライブラリ用） |
| `extern x : T = init;` | **外部 runtime 入力**（観測ごとに凍る scalar）。値はソースに書かず実行環境（Web の slider など）が供給する |
| `extern hold x : T [= init];` | **live な外部入力**。型が `Stream _` なら走行中に動く値（slider）、`Trigger _` ならイベント（ボタン・init 不要）（[音とストリーム](user/stream.md#宣言の-22let--hold--extern--extern-hold)） |
| `hold x = e;` | **コード定義の持続ストリーム**（ライブコーディング用）。構文は let と同じで、走行状態が編集を越えて生き、編集は crossfade で繋がる |
| `nominal X params = RHS;` | 剛体な名前つき型（[型システム](user/types.md#nominal-型)） |
| `enum X params { tag payload, … };` | payload 付き列挙型（[型システム](user/types.md#enum)） |
| `instance x : T = e;` | インスタンス（探索対象になる値。[クラス](user/classes.md)） |
| `instance e;` / `instance open e;` | 無名インスタンス / レコードの全フィールドをインスタンス化 |
| `infixl 6 +;` `infixr …;` `infix 4 ==;` | 演算子の結合性と優先順位の宣言 |
| `import M;` ほか | モジュール取り込み（[モジュール](user/modules.md)） |
| `private let …;` `private opaque …;` | モジュールローカル可視の修飾 |
| `#[node] {…}` | 直後の宣言への注釈（Web のノード表示・意味には効かない。[Web 環境](user/web-ui.md)） |

**⚙ 実装メモ**：`opaque` はネイティブ実装の供給点で、対応する実装が無い名前は
引数を集めたまま止まった値（stuck）として振る舞います（要検証：ユーザーモジュールでの用途）。

## 項（式）

### λ 抽象

```
λx. e                      -- 素の束縛子（check 位置で型が決まる）
λx y. e                    -- 複数束縛子
λ(x : A). e                -- 型注釈つき（これがあれば infer 位置でも型が決まる）
λ(a b : N)(c : R). e       -- グループ束縛子（同じ型の並び・複数グループ）
λ(?A : U). e / λ?a x. e    -- implicit 束縛子（? 前置）
```

束縛子列の構文は Π 型・`nominal` のパラメータと共通です。

### 関数型（Π 型）

```
A -> B                     -- 非依存
(x : A) -> B               -- 依存（B の中で x が使える）
(a b : N) -> B             -- グループ
(?n : N) -> Vec n R -> R   -- implicit 引数（呼び出し時は推論で補われる）
```

### let

let は宣言（`let x = e;`）のほかに、式の中でも使えます。

```
let inc : N -> N = λx. x + 1 in inc 4     -- let … in 式
{ let d = x * x; [ x / d, y / d ] }        -- ブロック：let の連鎖＋最後の式
```

`let` に**再帰は書けません**。定義の右辺から自分自身（や後続の宣言）は参照できず、
反復は `iterate` / `for` で表します（[評価モデル](user/evaluation.md)）。

ブロック・`in` の位置に書ける宣言は `let` だけではありません。
**`nominal`・名前付き `enum`・`instance`・fixity 宣言も式の中に書けます**
（`宣言; 続きの式` の形。ローカルな型・インスタンス・演算子を作れる）。
トップレベル専用なのは `import` / `private` / `opaque` / `extern` / `hold` / `#[node]` です。

### 制御

```
if c then a else b
case e of { some x => x, none => d }       -- enum の分岐（網羅必須）
```

`case` の arm は payload を束縛できます（`some x =>`）。分岐は網羅していないとエラーです。

### データ

```
[a, b, c]                  -- Vec リテラル（型は Vec 3 T）
{x = 1.0, y = 2.0}         -- レコードリテラル（フィールド名で対応・順序非依存）
{x : R, y : R}             -- レコード型
enum { nearest, linear }   -- 匿名 enum 型（式として書ける・let に束縛できる）
e.x                        -- レコード射影
v.0 / v.1                  -- Vec の成分アクセス（数値射影）
Interp.nearest             -- enum のタグ（型への射影記法）
```

**⚙ 実装メモ**：enum のタグは「型に対する射影」で取り出します。`Interp` のような
匿名 enum 型を `let` に束縛すると `Interp.nearest` が使えます。payload 付き enum の
コンストラクタ（`some` など）は宣言時に束縛される**ただの関数**です。

### 型注釈

```
[1, 2, 3] as Vec (1 + 2) N      -- 後置注釈 as（型の中の算術は正規化される）
((λx. x + 1) as N -> N) 10      -- λ 全体に注釈するには括弧で囲む
```

`as` は**注釈であって変換（coercion）ではありません**。`nominal` 型でも同じで、
リテラルに `as Complex` と書くのは「このリテラルは Complex として生まれる」という指定です
（[型システム](user/types.md#nominal-型)）。

### 折り畳みマーカー `@`（表示専用）

```
@e / @(…)                 -- 部分式をノードグラフ上で 1 ノードに畳む（無名）
@"name"(…)                -- 畳んだノードに表示名を付ける
let @x = e in body        -- let の値をノードに吸収する（値のノードを分けない）
```

`@` は**意味・型に完全に透過**な装飾です（評価・型検査は素通しで、表示だけが変わる）。
グラフのノード粒度を著者が制御するためのもので、テキスト↔グラフの往復で保存されます
（[Web 環境](user/web-ui.md#ノードの粒度と折り畳み-)）。

### ホール

```
?     -- 問い合わせ：期待される型を報告する。未完成の印（エラーにはならず「未完成」として扱う）
_     -- ワイルドカード：推論で決まるなら黙って埋まる。決まらなければ推論不能エラー
```

`?` を含むプログラムは**正規の状態**です。編集・読み込み・他の部分のプレビューは続けられます。

## 演算子

- 中置 `a + b` は `_+_ a b` に脱糖されます。演算子は `_+_` という名前の
  **ただの関数**として標準ライブラリが定義しています（専用機構なし）。
- 前置は `-x` → `-_ x`（`-_` / `+_` が定義済み）。
- `_+_` は**関数形のままでも使えます**（`_+_ a b`・高階関数に渡す・部分適用など普通の関数と同じ）。
- ユーザーも同じ形で独自演算子を定義できます：`let _⊕_ : … = …;` ＋ fixity 宣言。
- **記号にデフォルトの fixity はありません**。`infixl 6 +;` すら `std` が宣言しています。
- fixity 宣言のない演算子も、**優先順位の比較が要らない位置**（その階層で唯一の演算子）なら
  中置に使えます：`a ⊕ b` や `(a ⊕ b) ⊕ c` は OK。他の演算子と混ざる・連鎖するなど
  比較が必要になると曖昧エラーになり、fixity 宣言か括弧が要求されます
  （No ad-hoc：黙ってデフォルトの優先順位を当てない）。
- mixfix（`if_then_else_` のような穴あき記法）はありません。

標準の fixity（`std` 宣言）：

| 優先順位 | 演算子 | 結合 |
|---|---|---|
| 7 | `*` `/` | 左 |
| 6 | `+` `-` | 左 |
| 4 | `<` `==` `≡` | 非結合 |

## リテラル

| 書き方 | 型 |
|---|---|
| `3` | 数値（文脈から `N` / `Z` / `R` などに決まる。[クラス](user/classes.md#リテラルの解決)） |
| `1.5` | 小数（内部で `Rational` を経て `From` で解決） |
| `true` / `false` | `B` |
| `[a, b, c]` | `Vec 3 T`（文脈により nominal 型として生まれることもある） |
| `{x = …}` | レコード（同上） |

**⚙ 実装メモ**：リテラルの型は文脈から決まり、**決まらない場合は既定型に落ちず曖昧エラー**に
なります。たとえば `some 5` 単体が通らないのは `5` が `N`/`Z`/`R` のどれか決まらないためで、
`some (5 as N)` のように注釈すれば通ります。
