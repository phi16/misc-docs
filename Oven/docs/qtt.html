Oven ── 言語の記録

QTT ── 使用量を数える型

QTT(Quantitative Type Theory)は、各変数を「何回使うか」(multiplicity)を型で数える型理論です。Oven はこれを 消去(実行時に残さない)と 線形性(資源をちょうど一度使う)の両方に使います。線形性は効果系の土台です。

3 つの multiplicity

記法名前意味典型的な用途
'0消去0 回。型検査には要るが実行時には消える型インデックス・証明・サイズ
'1線形ちょうど 1 回(0 回でも 2 回でもダメ)GPU バッファ・IO token・状態
'ω無制限何回でも普通のデータ(省略時の既定)

構文は型の前に ' を置きます:'0 A、x : '1 A。すべての ' は直後の(原子か括弧の)型に掛かり、→ よりタイトに結合します('1 A → B は ('1 A) → B)。

半環と順序

+ :  0+x=x,  1+1=ω,  ω+_=ω        // 「2」を表す元がないので 1+1 は ω に丸める
· :  0·x=0,  1·x=x,  ω·ω=ω
順序 ⊑ :  反射 + 0⊑ω + 1⊑ω のみ(0 と 1 は比較不能)

0 と 1 が比較不能であることが要点です。これにより '1 は「ちょうど一度」という厳密な線形になります(「高々一度」ではない)。

Mult は第一級の値です(Mult : Type)。半環演算 +/·/⊔ を NbE が計算するため、'(1+1) A ≡ 'ω A が定義の等しさとして成立します。さらに 1 + 1 という 項 の評価も、専用構文ではなく Add(Mult) instance の解決として行われます(パーサは Mult を一切特別扱いしません)。

検査規則

型検査は使用ベクトル Δ(どの変数を何回使ったか)を同時に計算します:

  • 変数:x を使うと (x↦1, ほか↦0)。
  • 適用 f(a₁,…):Δ_f + Σ πᵢ·Δᵢ。各引数の使用量を binder の multiplicity で 掛けて 足します。πᵢ=0 なら 0·Δᵢ=0 ── その引数は実行時に使われない(=消去)。
  • ラムダ:本体で x を ρ 回使うとき ρ ⊑ π を要求。π=1 なら ρ=1 強制。
  • graded let:let 'm x : T = v; t。本体での使用 ρ ⊑ m を検査し、v の使用量は ρ 倍して足します(McBride/Idris 2 の graded let)。これで '1 資源(Buffer)を let でも線形に追えます ── let '1 out = newBuffer(n) の複製はエラーになります。mult は名前の前(let '1 out = …)、型注釈は省略すると値から推論、無印は 'ω です。
  • 型の検査は demand 0:型として検査される位置は使用量を 0 に強制します。型は実行時資源を食いません。
  • 分岐の合流:各枝の使用ベクトルを点ごとの上限 ⊔ で合流。⊔(1,0)=ω なので、線形変数を片枝でしか使わないと ω に化けて後段の '1 検査で弾かれます ── 線形は「全枝でちょうど一度」。

case の使用量規則

ここは Oven 独自色の強い部分です。case[P](v){ c₁(xs)=>b₁, … } の使用量は、branch を ⟦⟧ を使う(再帰)群と使わない(非再帰)群に分け、群内は ⊔-merge、群間は SUM で測ります:

Δ(case) = π_scrut·Δ_scrut + ⊔(⟦⟧ 無しの branch) + ω·⊔(⟦⟧ ありの branch)

なぜこの形か:

  • 群内 ⊔:実行時に通る branch は一つ(排他)。分岐は既存の合流と同じ。
  • 再帰群に ω を掛ける:⟦⟧ を使う branch は展開で動的な回数だけ走ります。外側の '1 を capture すれば ω·1=ω で弾かれる ── 再帰をまたぐ線形状態は ⟦⟧(帰納仮説)を通すしかない、が型から強制されます。
  • 群間が SUM である理由:fold では基底(zero 枝)も step(succ 枝)も 両方 走ります。両者を同じ ⊔ プールに入れると、「基底で 1 回使った線形」と「step で 0 回」が ⊔(1,0)=ω に化け、正当な線形 fold を誤って弾いてしまう ── 実際、以前の eliminator 版の規則(⨆_c u_c·Δcapture)にはこの穴がありました。基底=必ず走る(SUM)・同種枝=排他(⊔)・再帰=動的回数(ω)を分けて初めて健全かつ完全になります。

この規則により、線形資源を基底に入れて ⟦⟧ で threading する効果ループ が型付きます:

// 資源 S を threading しながら n 回反復。succ 枝は ⟦k⟧(前段の結果)を線形に通すだけで
// 外側の '1 を使わない → Δ = {s0:1} で通る
iterateEff : [A : '0 Type, S : '0 Type]
  (n : Nat, body : ('1 S, A) → ('1 S, A), s0 : '1 S, x0 : A) → ('1 S, A)
iterateEff[A,S](n, body, s0, x0) =
  case[λ(k) ('1 S, A)](n) { zero => (s0, x0),  succ(k) => body(⟦k⟧) }

先行との比較:Idris 2 は eliminator を持たず一般再帰 + totality 検査で反復を書き、再帰回数を usage で数えません(本体を 1 回検査・再帰呼び出しは 1 apply)。Oven は反復を case の構造的再帰に限定した代償として ω と群分けを規則として持ちますが、この SUM 規則で表現力は Idris の線形 fold と等価になります。

既知の穴(M0.5 対応予定):一般 inductive で非再帰 constructor が動的回数走る型(例:二分木の葉)では「⟦⟧ 無し = 高々 1 回」の前提が崩れます。組み込みの Bool/Nat/Fin/Vec は基底 constructor が高々 1 回なので健全ですが、ユーザ定義の分岐木には群の決め方の一般化が必要です。

scrutinee の量は payload に流れる

case で潰すと scrutinee の量が constructor payload の binder に流れます(let (a,b)=p でペアの量が成分に流れるのと同じ)。Nat/Bool は payload が純粋なので見えませんが、Vec[1, A](線形 payload)を潰すときに効きます:

  • ⟦⟧ を使わない branch(1 段 peel)では、尾 xs は 1 回しか現れないので 'ρ のままで健全(uncons 相当)。
  • ⟦⟧ を使う branch で線形データを再帰するとき は、iota で再帰位置が「branch 引数 xs」と「再帰結果 ⟦xs⟧」の 2 回現れます。そこで xs 自体は '0(消去)にして、使用を ⟦xs⟧ の 1 回に絞ります。xs は型に名前が要るだけで、実行時の値は ⟦xs⟧ が持つ ──「依存は型だけ・消費は帰納仮説経由」という線形依存型の定石です(Idris 2 で index/predecessor が quantity 0 なのと同じ)。

この「尾を '0 にする」扱いは、原理から出た解ではなく iota の double-use を避ける会計上の workaround である、と設計ノートは自覚的に記録しています(→ 現状と未解決)。線形 payload の自動 '0 化はまだ未実装です(ρ=ω の純粋データは double-use が起きないので現状でも問題なし)。

multiplicity 多相

Mult : Type なので multiplicity 多相はただの依存量化です:

id : [A : '0 Type] (p : Mult, x : 'p A) → A

'p(変数 multiplicity)入りの検査は「使用量 ⊑ p」という制約を生みますが、半環が有限(3 値)なので原理的には全部決定可能 です:f[p₁…pₖ] が valuation v で型付くかは f[v] を具体的に検査するだけなので、3ᵏ を全列挙すれば「通る valuation の集合」が完全に求まります。難しいのは決定可能性ではなく、集合を抽象のまま伝播・表現することと病的に大きい k で、そこは「未実装」として弾く方針です。

現状の実装は「閉じた multiplicity の完全検査 + postulate された多相プリミティブ」です。postulate は body が無いので使用量検査自体が無く、呼ぶ側は具体値に instantiate するためタダで済みます。ユーザ定義の mult 多相関数(列挙チェック)は将来です。

closure は 'ω だけ capture する

関数型を A → B 一種類に保つ要の規則です(→ 設計原理):

  • closure と部分適用が capture できるのは 'ω の値だけ。'1 資源は capture せず、常に引数で渡す。
  • これにより関数値はすべて 'ω(何度でも呼べる)になり、関数型は一様に A → B。
  • 帰結として、'1 引数の部分適用(g = f(buffer) でバッファを握った関数を作る)はできません。「状態を抱えた関数値」が本当に欲しければ、組み込みではなく手書きの Σ (Env : Type, env : Env, step : (Env, A) → (Env, B)) を値として書きます(Type : Type なので Env は第一級フィールド)。

この 2 規則('1 capture 不可・'1 部分適用不可)だけから、効果 token の escape 防止が新機構なしで閉じます。→ 効果系
